Pass - 16（二次渲染）

Pass-16 会先按文件类型读取图片，然后重新生成一张图片：

PNG 和 GIF 也有对应处理。原始上传文件会被删除，最终只保留 GD 库重新编码后的图片。

这种方式称为二次渲染或图片重编码。它会丢弃原文件中未参与图片结构的数据，通常可以破坏附加在图片末尾的脚本内容，因此比单纯检查文件头更严格。

要通过这一关，文件必须是真实且能被 GD 正常解析的图片；仅仅在普通文本前面添加图片头通常会在 imagecreatefrom*() 处失败。二次渲染后的文件仍应放在禁止脚本执行的目录中。

Pass - 17（先保存后校验，条件竞争）

Pass-17 的顺序存在明显问题：

程序先把文件写入上传目录，再检查后缀。非法文件会随后删除，但在“写入”和“删除”之间存在短暂窗口，这属于竞态条件（TOCTOU）问题。

理论上，如果另一个请求能在这段时间访问该文件，就可能在删除前读取它；实际是否可观察到取决于服务器速度、并发和文件系统，通常需要大量并发请求，结果也不稳定。

这关的安全重点是校验顺序：应先完成类型、内容和权限校验，确认安全后再写入最终目录；不要把不可信文件先放进可访问的 Web 目录。

Pass - 18（上传类的白名单校验）

Pass-18 使用 MyUpload 类处理文件上传。核心校验包括：

允许的扩展名是一个白名单，包含图片、文档和压缩文件等类型；.php 不在白名单中。类还会检查：

  • 是否确实是上传的临时文件；
  • 上传目录是否可写；
  • 文件扩展名是否允许；
  • 文件大小是否超过限制；

Pass-18 的关键是白名单校验比黑名单更可靠，但扩展名白名单仍不能替代文件内容检测。允许上传的 HTML、XML、压缩包等文件也可能带来其他风险，因此生产环境应只允许业务真正需要的类型。

Pass - 20（数组参数绕过）

Pass-20 同时校验上传 MIME、保存文件名后缀，并支持数组形式的 save_name：

关键点是：普通字符串会先经过 strtolower() 和 explode()，但如果提交的 save_name 是数组，代码会跳过 explode()。随后 end()、reset() 和数组下标操作分别参与后缀判断和最终文件名拼接，因此这是一个 PHP 数组参数类型混淆问题。

这一关还检查了客户端提交的 MIME 类型；MIME 值本身可被修改，所以不能作为唯一的安全依据。最终文件名仍应使用服务器端生成的安全名称，并结合真实图片内容检测。

总结

文件上传漏洞可能导致：

  • 上传恶意脚本，进一步造成服务器代码执行；
  • 获取服务器控制权，执行系统命令；
  • 读取、修改或删除服务器上的敏感文件；
  • 窃取数据库账号、用户信息和配置文件；
  • 上传钓鱼页面或恶意文件，影响其他用户；
  • 覆盖系统文件，造成网站篡改或服务中断；
  • 利用超大文件或大量文件消耗服务器存储和资源。

防御方法

  • 在服务端使用白名单，只允许业务需要的文件类型；
  • 验证真实文件内容，不能只相信扩展名或 MIME 类型；
  • 由服务器随机生成文件名，禁止用户控制保存路径；
  • 将上传目录放在 Web 根目录之外，或禁止脚本执行；
  • 限制文件大小、数量和上传频率；
  • 对图片进行重新编码或二次渲染；
  • 先完成校验，再保存到最终目录，避免条件竞争；
  • 下载文件时设置正确的响应头，防止浏览器执行恶意内容；
  • 对上传行为记录日志并进行病毒或恶意文件检测。

核心原则是：不信任客户端提供的信息，并确保上传文件即使被成功保存，也不能被服务器当作代码执行。

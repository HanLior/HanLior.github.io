4.SQL注入流程方法总结

4.1.判断SQL注入是字符型还是数字型

4.1.1.方法一：order by法

构造payload为：id=1 order by 9999 --+

  • 如果正确返回页面，则为字符型
  • 否则，为数字型

字符型执行的sql语句为select * from user where id=’1 order by 9999 –+’,注释符【- -】实际上在执行的时候，被当成id的一部分，也就是说，在执行sql语句的时候，条件是id=’1 order by 9999 –+’。最终只会截取前面的数字，返回id=1的结果。
如果是数字型的话，执行的sql语句为select * from user where id=1 order by 9999 –+,在现实生活中，根本就没什么可能会存在有9999个字段的表，所以会报错。

4.1.2.方法二：逻辑判断法

id 一般在数据库存储都是int 类型，username和password 肯定是字符类型的

4.1.3.方法三：常规方法

先测?id=1' 报错

数字型

?id=1 and 1=1 --+ 逻辑对，不报错

  • 查询语句为select from user where id=1--+

?id=1 and 1=2 --+ 逻辑不对，报错

  • 查询语句为select from user where id=2--+

字符型

?id=1 and 1=2--+不报错：因为被当作整个字符串处理了

  • 查询语句select from user where id='1 and 1=2--+'
  • id这个属性mysql 查询到 1 后面的第一个字母，就停止了，模糊判断1 and 1=2--+为 1

4.5.报错注入

4.5.1.xpath报错注入（extractvalue和updatexml）

在mysql高版本（大于5.1版本）中添加了对XML文档进行查询和修改的函数：

updatexml(XML_document, XPath_string, new_value)

extractvalue（XML_document，xpath_string)

当这两个函数在执行时，如果出现xml文档路径错误就会产生报错

updatexml(para1,para2,para3)用于修改para1 文件名、para2 文件路径 Xpath、para3 新值

extractvalue(para1,para2)用于修改para1 文件名、para2 文件路径 Xpath

payload 都在 para2 处，区别只是有没有 para3，para1 和 para3 随意填即可

当 xml 文档路径错误，会报错，使用时当xpath_string格式出现错误，mysql则会爆出xpath语法错误（xpath syntax）

updatexml()函数

updatexml(XML_document, XPath_string, new_value)

  • updatexml（）是一个使用不同的xml标记匹配和替换xml块的函数。
  • 作用：改变文档中符合条件的节点的值
  • 语法： updatexml（XML_document，XPath_string，new_value） 第一个参数：是string格式，为XML文档对象的名称，文中为Doc 第二个参数：代表路径，Xpath格式的字符串例如//title【@lang】 第三个参数：string格式，替换查找到的符合条件的数据
  • updatexml使用时，当xpath_string格式出现错误，mysql则会爆出xpath语法错误（xpath syntax）
  • 例如： select * from test where id = 1 and (updatexml(1,0x7e,3)); 由于0x7e是~，不属于xpath语法格式，因此报出xpath语法错误。

使用方法

extractvalue()函数

extractvalue（XML_document，xpath_string)

  • 此函数从目标XML中返回包含所查询值的字符串 语法：extractvalue（XML_document，xpath_string） 第一个参数：string格式，为XML文档对象的名称 第二个参数：xpath_string（xpath格式的字符串） select * from test where id=1 and (extractvalue(1,concat(0x7e,(select user()),0x7e)));
  • extractvalue使用时当xpath_string格式出现错误，mysql则会爆出xpath语法错误（xpath syntax）
  • select user,password from users where user_id=1 and (extractvalue(1,0x7e));
  • 由于0x7e就是~不属于xpath语法格式，因此报出xpath语法错误。

4.6.布尔盲注

布尔盲注的核心是：页面不直接显示查询结果，只根据条件为真或假表现出不同状态。你通过构造一系列真假问题，逐步推断数据。

大概思路是这样

函数 用途 示例
DATABASE() 当前数据库名 DATABASE()='security'
LENGTH() 字符串长度 LENGTH(DATABASE())=8
SUBSTRING() 截取指定位置字符 SUBSTRING(DATABASE(),1,1)
ASCII() 字符转 ASCII 数值 ASCII(SUBSTRING(DATABASE(),1,1))=115
ORD() 也可获取字符数值 ORD(SUBSTRING(DATABASE(),1,1))=115
COUNT() 统计行数 COUNT(*)=4
IF() 根据条件选择结果 IF(条件,1,0)

4.7.时间盲注

在SQL注入过程中，无论注入是否成功，页面完全没有变化。此时只能通过使用数据库的延时函数来判断注入点一般采用响应时间上的差异来判断是否存在SQL注入，即基于时间型的SQL盲注
select id,name from product where id=1 and sleep(2)

总结

SQL 注入的主要防御方法有：

  • 使用参数化查询或预编译语句，避免直接拼接用户输入；
  • 对输入进行类型和格式校验，例如 ID 只允许整数；
  • 数据库账户使用最小权限，禁止不必要的增删改和文件操作权限；
  • 不向用户直接返回详细 SQL 错误信息；
  • 避免使用黑名单过滤关键词，因为容易被绕过；
  • 对关键操作进行权限验证和日志记录；
  • 定期进行代码审计和安全测试。
